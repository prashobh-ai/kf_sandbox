# Deploying to GitHub Pages

This is a static site: a build step turns `docs_source/` into `site/data/index.json`,
and GitHub Actions publishes the `site/` folder to GitHub Pages. No backend, no
API keys. The in-browser AI (semantic search + optional WebLLM synthesis) loads
its models from public CDNs at runtime in the visitor's browser.

The published URL is derived from the **owner** and **repo name**:

```
https://<owner>.github.io/<repo>/
```

e.g. repo `prashobh-ai/Knowledge-Fabric` → `https://prashobh-ai.github.io/Knowledge-Fabric/`.

---

## One-time setup for a new owner/repo

Two of these steps can only be done by the repo owner — a CI token cannot enable
Pages or turn on Actions for you (`Resource not accessible by integration`).

### 1. Seed the repo with this code

**Easiest — GitHub import (server-side copy):**
1. Go to <https://github.com/new/import>
2. *Clone URL:* the source repo's `.git` URL
3. *Owner:* the target account (e.g. `prashobh-ai`) · *Name:* `Knowledge-Fabric` → **Begin import**

If the source is private and import asks for credentials, either make the source
public briefly, or use the bundle method below.

**Fallback — push a git bundle** (created with `git bundle create Knowledge-Fabric.bundle --all`):
```bash
git clone Knowledge-Fabric.bundle Knowledge-Fabric
cd Knowledge-Fabric
git remote set-url origin https://github.com/<owner>/Knowledge-Fabric.git
git push -u origin main
```

### 2. Enable Actions (owner)

Imported repos start with Actions disabled. Open the repo's **Actions** tab and
enable workflows if prompted.

### 3. Enable Pages (owner)

**Settings → Pages → Build and deployment → Source → GitHub Actions.**

(Do not choose "Deploy from a branch" — the site lives in `site/` and its
`index.json` is generated by CI, so branch-root serving would only show this README.)

### 4. Deploy

Push any commit to `main`, **or** run it manually: **Actions → "Build and Deploy
to GitHub Pages" → Run workflow → main**.

The workflow (`.github/workflows/deploy.yml`) installs the pipeline deps, builds
`site/data/index.json` (including semantic embeddings), and publishes `site/`.
When it finishes, the site is live at `https://<owner>.github.io/<repo>/`.

---

## Everyday updates

Just push to `main`. CI rebuilds the index and redeploys automatically. To add or
remove source documents, edit `docs_source/` and push — nothing else required.

## Local preview

```bash
./scripts/dev.sh            # builds the index and serves the site on :8000
```

`site/data/index.json` is `.gitignore`d on purpose — CI regenerates it on every
deploy, so it is never committed.

## Notes on the in-browser AI

- **Semantic search** loads a small model (~23 MB, WASM) automatically; it works
  in any modern browser.
- **AI synthesis** is opt-in via the "Enable AI synthesis" button and needs
  **WebGPU** (recent Chrome/Edge). The model (~0.9 GB) downloads once and is cached
  — preload it before a live demo, on good network.
- If either model can't load, the app degrades gracefully (semantic → keyword,
  synthesis → extractive). The curated answers in `site/data/demo_answers.json`
  always render instantly regardless, since they need no model.
